# SEO, AEO and local search plan

## Positioning and intent

Primary geographic focus: Ranebennur, Haveri district, Karnataka. The site should help patients find accurate local hospital information and reach the right human contact. Avoid keyword stuffing and unsupported superlatives.

Candidate query themes (validate with Search Console/keyword research and actual service availability):
- Shivam Hospitals Ranebennur
- Shivam Hospital Ranebennur address / phone / directions
- multispeciality hospital in Ranebennur
- orthopaedic hospital / orthopaedic doctor in Ranebennur
- dermatologist in Ranebennur
- neurology / general surgery / urology / ENT in Ranebennur
- hospital appointment Ranebennur
- Ayushman Bharat / PM-JAY hospital Ranebennur (only if status and packages verified)

Do not create pages for specialities the hospital does not currently provide.

## On-page standards

- One clear H1 per page reflecting the actual service and location where appropriate.
- Unique, useful title and meta description for each indexable page.
- Canonical URL, descriptive slug, Open Graph metadata and social preview.
- Descriptive internal links and breadcrumbs.
- Image alt text describing the actual image; decorative images use empty alt.
- Fast, indexable server-rendered HTML; no critical content hidden behind client JavaScript.
- Human-reviewed medical copy; show reviewer/date where clinically meaningful.
- FAQs based on genuine questions; answer directly and avoid medical diagnosis.
- Keep name, address, phone and hours identical across footer, contact page, Google Business Profile and directories.

## Structured data

Use JSON-LD only when it matches visible, verified page content. Candidate types:
- Hospital or the most appropriate Schema.org medical organisation type after checking current vocabulary.
- Organization / LocalBusiness only where accurate and not duplicative.
- Physician for individual clinician profiles after credentials and affiliation are verified.
- BreadcrumbList for navigation.
- FAQPage only when the page visibly contains the same FAQs; do not expect FAQ rich results.
- WebSite / WebPage where useful.

Never invent ratings, review counts, geo coordinates, opening hours, medical specialties, credentials or sameAs links. Do not add aggregateRating or review markup solely to seek stars; only use eligible, genuine, accurately represented data and comply with search-engine policies.

## Local presence

- Confirm and clean up exact Google Business Profile name, address, phone, category, hours, map pin and URL.
- Verify profile ownership and website URL with client.
- Ensure NAP consistency in local directories and social channels.
- Link to the canonical Google Maps directions/profile.
- Use real location photographs and accurate captions.
- Add a visible route/directions experience; avoid embedding a heavy map high in the page if a simple link is sufficient.

## Technical SEO

- XML sitemap and robots.txt.
- Search Console verification and sitemap submission.
- Correct index/noindex behaviour for preview and private routes.
- Redirect plan for any old client domain URLs.
- 404 and canonical checks.
- Mobile usability, Core Web Vitals and image optimisation.
- Avoid duplicate speciality content and doorway pages.
- Analytics only after privacy review and configuration.

## AI search / AEO

- Answer-first, factual sections for hospital identity, address, departments, doctors and appointments.
- Clear page headings, descriptive internal links and consistent entity details.
- Clinician and service facts should be attributable and maintained.
- Provide concise FAQs drawn from actual patient questions.
- `llms.txt` may be considered as an optional machine-readable orientation file, but is not a substitute for crawlable pages, structured data, factual consistency or Search Console.
